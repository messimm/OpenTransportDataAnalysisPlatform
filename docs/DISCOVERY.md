# Видимость проекта в поиске / Project discovery

Код репозитория может улучшить содержание поисковой выдачи, но название,
короткое описание, topics и URL проекта на GitHub настраиваются владельцем
репозитория в интерфейсе GitHub.

## Рекомендуемое описание GitHub

> Модульная Python-платформа для анализа транспортных данных и городской
> мобильности: data.mos.ru, пассажиропотоки, обеспеченность районов,
> воспроизводимые pipeline и визуализации.

## Рекомендуемые GitHub Topics

```text
transport-data urban-mobility public-transport transport-analytics
mobility-analysis geospatial-analysis open-data data-mos-ru moscow
python data-analysis research-software
```

## Что уже находится в репозитории

- название и предметная область в первых строках `README.md` на русском и английском;
- ссылки на источники, готовые кейсы и команды запуска;
- `CITATION.cff` для научного цитирования и индексации;
- `llms.txt` и `AGENTS.md` для кодовых агентов;
- отдельные страницы задач и документации модулей.
- российский online-пример `data.mos.ru` и международный пример стандарта GBFS.

## Что нужно сделать владельцу после merge

1. Заполнить поле **About** предложенным описанием.
2. Добавить Topics из списка выше.
3. Указать официальный URL проекта, если он существует.
4. Включить Issues и добавить issue templates, если планируется внешнее участие.
5. После появления релизов создать первый GitHub Release с понятным changelog.

Эти настройки нельзя надёжно изменить pull request-ом: они относятся к
метаданным самого GitHub-репозитория.
